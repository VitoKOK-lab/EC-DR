# 選品清單（A）— 設計與施工計畫

> **一句話**：設計師貼一個 Shopline 商品網址，系統把名稱、照片、價格抓回來，
> 按月份列成一張清單；行銷看得到這個品以前有沒有影片賣過，賣過就排二創、沒賣過就排新片。

這是「選品 → 影片 → 投廣 → 算錢」四段裡的**第一段**。
A 沒有任何外部相依，可以自己上線，也不會動到現在天天在跑的東西。

---

## 這一份**不做**什麼

寫下來是為了以後不會偷偷長大：

- ❌ FB 投廣、廣告花費（那是 C）
- ❌ Shopline 營收匯入、ROAS、加投建議（那是 D）
- ❌ 檔期 —— 老闆決定改成**按月份**，不做檔期這個東西
- ❌ 審核關卡 —— 設計師送出就直接進清單
- ❌ 把現有 223 個舊商品名建檔 —— 設計師從官網自己選，舊的不管
- ❌ 動到二創、新片、影片庫、影片成效 —— **一行都不碰**

---

## 為什麼是「清掉重做」不是「接著改」

系統裡有一套 v138 做的「選品配對」，v175 整頁拆掉了，程式碼裡留著一句
「老闆要重新設計」。資料庫裡剩下：

| 集合 | 筆數 | 內容 |
|---|---|---|
| `products` | 2 | 一筆叫 `test`（官網連結欄位寫「2」）、一筆是 Regina 建的「歐泊項鏈」 |
| `matches` | 2 | 一筆 test 被退回、一筆 Regina 9/1 送出到今天沒人審 |

老闆的判斷：**設計錯誤，沒有人在用，重做就好。**

錯在哪：那一版是「選品的人從商品出發挑一支影片，送老闆審核」。
這次的流程反過來 —— **設計師先給清單，行銷再排**，而且**沒有審核**。
老闆不當守門員，他看清單就好。

所以：`matches` 整個退役，`products` 留著（欄位對、規則和備份清單都已經涵蓋）
但那 2 筆垃圾清掉。

## 角色與權限

### 新職位「設計師」

加一個 `design`，跟現有十個職位並列。他登入只看得到 **傳訊息**、**選品** 兩頁。

⚠️ **設計師不下載影片資料**。量過：整包影片 **2.5 MB**（1,061 支）。
設計師只負責挑品，不需要那些資料，沒道理讓他的手機每次開機付這個成本。

### 兩個新權限（照 v207 的規矩：職位不給預設，逐人勾）

| 權限 | 它在畫面上的哪裡 | 誰會勾 |
|---|---|---|
| **選品** | 上面的分頁 | 設計師、行銷、經理人 |
| **排影片** | 選品 → 點商品 → 排二創／排新片 | 行銷、經理人 |

**勾了「排影片」的人才下載影片資料** —— 因為他要挑素材。
這一條把「誰付下載成本」跟「誰真的需要」綁在一起，不再綁死在職位上。

## 畫面：一個新分頁「選品」

### 設計師看到的

```
┌─ 選品 ────────────────────────────────┐
│  [ 貼上 Shopline 商品網址 ]   ＋新增    │
│                                        │
│  2026 年 9 月（3 個）                   │
│  ┌────┐ 自帶光芒｜手鏈｜天然歐泊         │
│  │ 圖 │ 售價 NT$990～3,500              │
│  └────┘ 原價 NT$6,000～15,000  4 款      │
│         ✎ 改  🗑 刪                     │
│  …                                     │
│  2026 年 8 月（5 個）…                  │
└────────────────────────────────────────┘
```

- **只要貼一個網址**，名稱／照片／價格都自動回來
- 按月份分組，自動掛當月；月底要選下個月的品，可以改月份
- 新增、編輯、刪除都他自己來，不用等人審

### 行銷／經理人多看到的

每一列右邊多一塊：

```
以前賣過 3 支影片 ┊ 最好的一支 87 萬觀看 ┊ [ 排二創 ]
沒有賣過                                  ┊ [ 開新片 ]
```

按下去就走**現在已經在跑的**二創或新片流程，不另外做一套。

## 資料形狀

沿用 `products` 集合（安全規則、備份清單、即時訂閱都已經有了，不另開）。

```
products/{id}
  ── 既有，不動 ──
  id            文件編號
  name          商品名稱
  officialUrl   Shopline 商品網址
  sku           貨號
  image         主圖
  aliases[]     曾用名（改名時舊名推進來）
  oldUrls[]     舊網址（換連結時舊的推進來）
  status        on / off（官網下架仍保留紀錄）
  offAt         下架時間

  ── A 新增 ──
  pickedBy      誰選的
  pickedAt      什麼時候選的
  pickMonth     掛在哪一個月（YYYY-MM）
  note          設計師備註

  priceMin/priceMax        售價區間（抓回來的）
  listMin/listMax          原價區間（抓回來的）
  variants[]               款式名稱
  fetchStatus              pending / ok / failed
  fetchedAt / fetchError   什麼時候抓的、失敗原因

  soldVideoIds[]           以前賣過這個品的影片（系統算，不是人填）
  soldStat                 {count, bestViews, bestVideoId}
```

`matches` 集合：**退役**。同時清掉安全規則、備份清單、`fb.js` 的訂閱。

## Mac mini 去抓商品資料

### 為什麼不能讓瀏覽器自己抓

官網 **沒有開 CORS**（實測：回應裡沒有 `Access-Control-Allow-Origin`）。
設計師手機上的網頁直接抓會被瀏覽器擋掉。

所以走現有的模式：Mac mini 去抓 —— 跟每天抓 Google Drive、抓 Meta 成效同一台、同一個做法。

### 實測抓得到什麼

拿資料庫裡現成的商品網址真的抓過一次：

| 欄位 | 從哪裡來 | 實測結果 |
|---|---|---|
| 名稱 | JSON-LD `Product.name` | 自帶光芒｜手鏈｜項鍊｜天然歐泊 |
| 照片 | JSON-LD `image[0]` | Shopline 圖床網址，可直接顯示 |
| SKU | JSON-LD `sku` | 685e233a558ae8000c15a2bd |
| **售價** | 頁面內嵌 JSON `price_sale` | **990 / 3,000 / 3,500** |
| **原價** | 頁面內嵌 JSON `price` | **6,000 / 13,000 / 15,000** |
| 款式 | `name_translations` | 白歐泊、黑歐泊、白歐泊項鍊、黑歐泊項鍊 |

⚠️ **一頁會有很多款，所以價格要存成區間，不是單一數字。**

### 體驗

```
設計師貼網址 → 送出 → 顯示「抓取中…」
      ↓（Mac mini 每 5 分鐘掃一次 pending）
自動變成 照片＋名稱＋售價區間＋原價區間
```

不用重整 —— 資料庫是即時同步的，抓完自己會跳出來。
抓不到就顯示「抓不到，請手動填名稱」，不讓他卡住。

### 只收商品頁

實測現有 166 支影片貼的網址：

| 貼了什麼 | 幾支 | 對得回單一商品嗎 |
|---|---|---|
| `/products/...` | 125 | ✅ |
| `/pages/...` 活動頁 | 26 | ❌ |
| `/categories/...` 分類頁 | 15 | ❌ |
| 首頁 | 1 | ❌ |

**四分之一貼的不是商品頁。** 所以送出時就擋：不是 `/products/` 就直接告訴他
「這是分類頁，請貼單一商品的網址」。抓得到名稱和價格本身就是最好的驗證。

## 「這個品以前賣過嗎」怎麼算

設計師不下載影片，所以不能在他的瀏覽器掃 1,061 支。

改成 **Mac mini 每晚那支同步工作順便算**，把結果寫進商品的 `soldVideoIds` / `soldStat`。
比對規則用現成的 `prodKey`（主檔 id → 官網連結 → 名字），不另外發明一套。

代價：**資料是昨天的**。對「這個品賣過沒」這種問題完全夠用。

---

## 怎麼驗

照這個專案的規矩：

1. `node tests/run-all.js` 要**全綠**才算數
2. 新增 `tests/smoke-v210.js`：權限、分頁、月份分組、只收商品頁、抓取中的狀態、
   賣過沒的顯示、設計師看不到別頁
3. 新增 `tests/shopline-parse.py`：**把抓回來的 HTML 存成樣本檔**，
   用它驗解析規則 —— 測試不打網路，官網改版時這支會變紅
4. 每加一道防護就**故意弄壞一次**，確認測試會變紅。測不到的防護等於沒有
5. 1400 與 390 兩個寬度都在真的瀏覽器上看過
