# 平台成效串接 — 你要做的那一步（2026-09 改版）

> 目標：把 FB 粉專／IG 各帳號的貼文成效（觀看、讚、留言、分享）自動抓回來，
> 對回系統裡的影片，寫進 `videos.metrics`，「平台成效」那一頁就自然有數字。
> 有了數字，「大流量影片」才有辦法自動挑，而不是靠人手動加。

---

## 這一版跟上一版差在哪（為什麼清單變短了）

上一版規劃的是：**Supabase 排程 → 用 Firebase 服務帳號金鑰寫回 Firestore → 用「影片標題」比對**。
三件事都換掉了：

| | 舊規劃 | 現在 | 為什麼 |
|---|---|---|---|
| 跑在哪 | 另開一個 Supabase 專案 | **Mac mini**，跟每天 03:00 的備份同一台 | 那台本來就在跑排程了，不用再多養一個服務、不用多一個帳號密碼 |
| 怎麼寫回資料庫 | Firebase **服務帳號金鑰**（等於資料庫萬能鑰匙，你要自己保管） | 跟網頁一樣的**匿名登入**，權限一模一樣 | 少一把萬能鑰匙要保管。備份腳本已經這樣跑半年了 |
| 怎麼對回影片 | 貼文標題＝影片 `name` | **文案比對** | 舊做法行不通：`name` 是內部檔名（「0819 黃鐵礦帶財」），平台貼文上根本沒有這串字 |

所以你原本的 A～E 五項，**現在只剩下 A 的一部分**。C（Supabase）、D（Firebase 金鑰）整個不用做了。
TikTok 那條線先擱著 —— IG／FB 佔了你們絕大部分的量，先把這邊跑通。

## 1. IG 帳號要先是專業帳號

IG 要抓得到「貼文洞察」，帳號必須是**商業或創作者帳號**，而且**連到一個 FB 粉專**。

> IG App → 設定 → 帳號類型與工具 → 切換為專業帳號 → 連結粉專

六個都要：`@tzgems1111`、`@tzgems5588`、`@tzgrotwofficial`、`@tzgems666`、`@tzgrotw`，以及 FB 粉專 `Zanagems`。

（LINE 社群沒有這種 API，抓不到，只能維持人工。）

---

## 2. 建一個 App

1. 到 <https://developers.facebook.com/> → 用你的 FB 登入 → 建立應用程式
2. 類型選「**商業（Business）**」，名稱隨意（例：`ZanaGems Insights`）
3. 加入產品：**Instagram Graph API**、**Facebook Login for Business**

### 會不會卡審核？

抓**自己名下**帳號的數據，在 App 還沒上線（開發模式）的狀態下，
只要操作的人是 App 的管理員，就已經可以用了 —— 這是先試跑的捷徑，**不必等 App Review**。

要讓它長期穩定跑（權杖不會因為 App 沒上線而被限制），還是要做**商家驗證**並送審這些權限：
`instagram_basic`、`instagram_manage_insights`、`pages_read_engagement`、`pages_show_list`、`read_insights`。

建議：**先用開發模式把整條線跑通給你看**，同時把商家驗證送出去（那關通常最久，一兩週跑不掉）。

---

## 3. 拿長期權杖

1. 到 <https://developers.facebook.com/tools/explorer/>（圖形 API 測試工具）
2. 右上選你剛建的 App → 「取得權杖」→ 取得使用者存取權杖
3. 勾上面那五個權限 → 產生 → 會拿到一串 `EAA...` 開頭的字（這是**短期**的，兩小時就過期）
4. 到 <https://developers.facebook.com/tools/debug/accesstoken/> 貼上去 → 按「延長存取權杖」
   → 換成 **60 天**的長期權杖
5. 順便在同一個工具裡按 `/me/accounts`，可以看到你管理的粉專清單與它們的 **ID**（一串數字）；
   每個粉專再查 `/{粉專ID}?fields=instagram_business_account` 就能拿到連著的 **IG 帳號 ID**

> 60 天到期前要換一次。換的時候只要改 `~/.ecdr-meta.json` 裡的 `token` 那一行就好。
> （之後可以改成用 App ID + Secret 自動續期，先不急。）

## 4. 寫進 Mac mini

在 Mac mini 上建一個檔案 `~/.ecdr-meta.json`：

```json
{
  "token": "EAA...（第 3 步拿到的長期權杖）",
  "accounts": [
    {"platform": "FB", "name": "FB 粉專（Zanagems）",        "pageId":   "粉專的數字 ID"},
    {"platform": "IG", "name": "IG 官方（@tzgrotw）",         "igUserId": "IG 的數字 ID"},
    {"platform": "IG", "name": "IG 溱姐主（@tzgems1111）",    "igUserId": "..."},
    {"platform": "IG", "name": "IG 泰熙爾汗（@tzgems5588）",  "igUserId": "..."},
    {"platform": "IG", "name": "IG 代理（@tzgems666）",       "igUserId": "..."},
    {"platform": "IG", "name": "IG 英文（@tzgrotwofficial）", "igUserId": "..."}
  ]

```

- **放家目錄，不要放在 repo 裡。** repo 是公開的，權杖進了 git 就等於貼在網路上。
- `name` 要跟系統「上片平台」那張清單的寫法**一字不差**，成效才會合在一起看。

## 先講清楚的幾件事

**一支片對到的不是一則，是好幾則。**
6 月的資料顯示，一支片是同時發 6 個 IG ＋ 1 個 FB ＋ LINE 社群。
所以一支片底下會有 7 列成效，「這支片的總觀看」是 7 個帳號加起來。
也因為這樣，「上片連結」那一格只放得下其中一則 —— 它是人工補救用的，
真正在對的是文案。

**有 170 支已上片的片沒有文案，對不回來。**
系統裡 416 支已上片的片，有文案的 246 支。8 月起幾乎都有填（8 月 107/108、9 月 51/53），
6–7 月只有一半。沒文案的那些只能靠人工填上片連結。
**所以「文案一定要填」從現在起是有實際用途的，不是多做一個欄位。**

**成效不是即時的。** 官方 API 給的是「現在的累計數字」。
「本週漲了多少」「粉絲成長」要靠每天存一份快照相減，那要接上之後跑滿一週才看得出來。

**銷售數字不在這裡。** API 只給觀看／互動。商品實際賣了多少要另接 Shopline 訂單，那是另一條線。
